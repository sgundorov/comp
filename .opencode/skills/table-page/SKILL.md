# Table Page Creation Checklist

Создание табличной страницы (`*_page.php`, `*_columns.php`, `*.php`, `*_form.php`, `*_save.php`) должно следовать шаблону `city.php` — эталонной реализации.

## 1. Подготовка — проверка схемы БД

Перед написанием кода проверить таблицу через `SHOW CREATE TABLE`:

```php
$q = $conn->query("SHOW CREATE TABLE <table>");
```

### 1.1 NOT NULL без DEFAULT
Каждое поле `NOT NULL` должно иметь `DEFAULT`, иначе INSERT упадёт:
```sql
`accept_flag` tinyint(1) NOT NULL          -- ❌ ОШИБКА
`accept_flag` tinyint(1) NOT NULL DEFAULT 0 -- ✅
```

### 1.2 UNIQUE KEY для авто-нумерации
Если есть поле `number` с автоинкрементом по типу документа, нужен `UNIQUE KEY`:
```sql
-- ❌ обычный KEY — дубликаты возможны, retry не сработает
KEY `typeop_number_key` (`typeop`,`number`)

-- ✅ UNIQUE KEY — дубликат вызывает 1062, retry перевычисляет number
UNIQUE KEY `typeop_number_key` (`typeop`,`number`) USING BTREE
```
**Без UNIQUE KEY** при параллельном открытии двух форм обе получат одинаковый `MAX(number)+1`, и вторая запись не вызовет ошибку 1062. Retry-цикл не сработает.

### 1.3 Все поля формы — в SELECT
`select_sql` / `count_sql` / `id_select_sql` должны SELECT-ить все поля, упомянутые в form + search + visible columns. Если поле только для поиска (невидимая колонка), оно всё равно нужно в SELECT и JOIN.

### 1.4 LEFT JOIN для всех FK
Все внешние ключи (client_id, store_id, sotr_id и т.д.) должны иметь LEFT JOIN для получения display-имени.


## 2. Конфигурация колонок (`config/{table}_columns.php`)

```php
function sale_columns_defaults() {
    return [
        ['name' => 'col', 'label' => 'Колонка', 'sort_expr' => 'd.col',
         'search' => true, 'filter' => false, 'export' => true,
         'param' => null, 'readonly' => false],
    ];
}
```

- `'label'` — короткий заголовок (`'Док. №'`, а не `'Документ №'`)
- `'search' => true` — поиск по этой колонке (по всем полям формы — отдельно)
- `'filter' => true` — колоночный фильтр (только для справочников)
- `'param'` — имя hidden-поля (для lookup, иначе null)
- `'readonly' => true` — авто-вычисляемые поля (id, number, sum); в таблице для них **не показывается инлайн-редактор**
- Удалять из defaults поля, которые не должны быть в таблице (например, `sum_discount`, если оно только в форме)
- Для полей-справочников (lookup), поле `'param'` автоматически даёт:
  - колоночный фильтр (если `'filter' => true`)
  - инлайн-редактор с lookup-выбором
  - `param` = имя hidden-поля, которое `render_data_js_tbl` передаёт в `data-param`
- **Форматирование чисел в ячейке**: в `{$cellValue}` используй `fmt_table_num()`:
  - `fmt_table_num($val)` — 0 → пусто, целое → без дроби, дробное → макс 2 знака
  - `fmt_table_num($val, true)` — суммы: 2 знака, 0 → пусто

## 3. Конфигурация страницы (`config/{table}_page.php`)

### 3.1 search_cols — ВСЕ поля формы
```php
'search_cols' => [
    'number'  => 'd.number',        // колонка таблицы
    'client'  => 'c.name',          // FK display-имя (JOIN)
    'zakaz'   => 'd.zakaz_num',     // поле только в форме
    'sotr'    => 'sotr.doc_name',   // FK только в форме (не колонка таблицы)
    'date_plat'=> 'd.date_plat',    // поле формы, невидимое в таблице
    // ...все поля формы...
],
```

**Правило**: `search_cols` должен включать **каждое поле из формы** (`sale_form.php`), даже если оно не является видимой колонкой таблицы. Иначе через панель «Условия поиска» будет невозможно найти запись по этому полю.

### 3.2 search_labels — названия для панели поиска
```php
'search_labels' => [
    'number'  => 'Документ №',
    'zakaz'   => 'По документу №',
    'sotr'    => 'Сотрудник',      // label для поля, которого нет в колонках
    'date_plat'=> 'Дата оплаты',
    // ...все search_cols ключи...
],
```

### 3.3 column_visibility_tbl
**Критично.** Если `marks_tbl` отличается от имени, используемого в `{table}_columns_save.php`, добавить `column_visibility_tbl`:

```php
'marks_tbl'       => 'docum',           // таблица для хранения отметок
'column_visibility_tbl' => 'sale',      // таблица column_visibility (отдельно)
```

По умолчанию (`if (!isset(...))`) `columnVisibilityTbl` равен `marksTbl`. Явно указывать, только если они различаются.

### 3.4 col_filters — настройка фильтров
```php
'col_filters' => [
    'client' => [null, 'client', 'client_id', 'name'],
    'store'  => [null, 'store', 'store_id', 'name'],
],
```

## 4. Главная страница (`{table}.php`)

### 4.1 SEARCH_COLS — из search_cols + search_labels
**НЕПРАВИЛЬНО** (только из видимых колонок):
```php
const SEARCH_COLS = <?= json_encode(
    array_values(array_filter(array_map(function ($c) {
        return $c['search'] ? ['key' => $c['name'], 'label' => $c['label']] : null;
    }, $COLUMN_DEFAULTS)))
) ?>;
```

**ПРАВИЛЬНО** (из search_cols конфига):
```php
const SEARCH_COLS = <?= json_encode(
    array_values(array_map(function ($key) use ($salePageConfig) {
        $labels = $salePageConfig['search_labels'] ?? [];
        return ['key' => $key, 'label' => $labels[$key] ?? $key];
    }, array_keys($salePageConfig['search_cols'])))
) ?>;
```

### 4.2 lookup_tables — все лукапы формы
```php
'lookup_tables' => ['client', 'store', 'sotr'],
```

Даже если один `data-lookup` используется на нескольких полях формы (например, `sotr` для Сотрудник и Принял), указывать его **один раз** — `form-modal-handler.php` теперь использует `querySelectorAll`.

### 4.3 lookup_data — когда данные в data-countries
**НЕ ставить** `lookup_data`, если данные лукапов встроены в HTML через `data-countries`. `lookup_data` нужен только если данные передаются через `window.*` переменную.

### 4.4 render_table_page_scripts — опции (lib/table-page-scripts.php)

```php
render_table_page_scripts([
    'pageUrl'        => 'city.php',
    'formPrefix'     => 'city_form',
    'tableKey'       => 'city',
    'fieldSaveUrl'   => 'city_field_save.php',
    'columnsSaveUrl' => 'city_columns_save.php',
    'columnResizeUrl'=> 'city_column_width_save.php',
    'visibleColumns' => $COLUMN_DEFAULTS,
    'defaultColumns' => $COLUMN_DEFAULTS,
    'exportUrl'      => 'city_export.php',
    'printUrl'       => 'city_print.php',
    'lookupData'     => ['client' => $clientList, 'store' => $storeList],
    'marksTbl'       => 'city',             // если задан — генерирует clearSelection/invertSelection/toggleShowOnly + getInvertUrl
    'searchPanelConfig' => [                 // расширенные опции SearchPanel
        'popupCheckboxes' => true,
        'emptyClass'      => 'search-cond-placeholder',
        'labels'          => ['cols' => 'Колонки', 'cond' => 'Условие'],
        'onApply'         => 'function(state) { ... }',   // строка JS-кода
        'onToggle'        => 'function(state) { ... }',
        'onSubmit'        => 'function() { ... }',
    ],
    'colFilters'     => [                    // авто-инициализация ColumnFilter
        ['thSelector' => '.col-client',   'pageUrl' => 'city.php'],
        ['thSelector' => '.col-status',   'pageUrl' => 'city.php', 'param' => 'status'],
    ],
    'formModalConfig' => [...],
    'extraCode'       => '',
]);
```

**Порядок генерации JS:**
1. `closeAllPanels()`, `__focusAfterSave()`
2. Чекбоксы отметок: `checkAll` + `.row-check` → `action=toggleSelect`
3. `SelectionToolbar.init()` с `getExportUrl`, `getPrintUrl` и (если `marksTbl` задан) `getInvertUrl`
4. `SearchPanel.init()` с базовыми опциями + расширения из `searchPanelConfig`
5. `SortPanel.init()`
6. `ExportModal.init()`
7. Если `marksTbl` задан: `window.clearSelection`, `window.invertSelection`, `window.toggleShowOnly`
8. Если `colFilters` задан: `ColumnFilter.init()` для каждого элемента
9. `render_form_modal_script()`
10. `ColumnsPanel.init()`
11. `RowSelect`, фокус, dblclick, хоткеи
12. `InlineEdit.init()` с данными из `lookupData`
13. `ColumnResize.init()`

### 4.5 formModalConfig — опции шаблона form-modal-handler.php

Шаблон `form-modal-handler.php` поддерживает следующие опции в `formModalConfig`:

```php
'formModalConfig' => [
    'autoInitTables'  => ['d2'],    // префиксы таблиц для auto-init (default [])
    'autoBindLookups' => true,      // авто-биндинг [data-lookup] (default true)
    'autoSetupTabs'   => true,      // авто-настройка .tab-handler (default true)
    'extra_open'      => '...',     // JS, выполняется ПЕРЕД autoInitFormBody()
    'extra_restore'   => '...',     // JS, выполняется ПЕРЕД autoInitFormBody()
],
```

**Порядок инициализации формы:**
1. Выполняется `extra_open`/`extra_restore`
2. `autoInitFormBody()` — биндит все не привязанные `[data-lookup]`, настраивает табы, вызывает `init<Prefix>Table()` для каждого `autoInitTables`

Если страница использует lookup + табы + вложенную таблицу, укажи только префикс таблицы в `autoInitTables`, остальное сделает шаблон.

### 4.6 render_embedded_subtable_scripts — опции шаблона

```php
render_embedded_subtable_scripts([
    'prefix'          => 'd2',
    'columns'         => $columns,
    'saveUrl'         => 'docum2_field_save.php',
    'parentField'     => 'docum_id',
    'childFormUrl'    => 'docum2_form.php',
    'childFormName'   => 'docum2_form',
    'totalsCallback'  => '',           // имя функции для пересчёта итогов
    'onSaveSuccessExtra' => '',
    'columnResizeUrl' => 'docum2_column_width_save.php',
    'columnResizeTbl' => 'docum2',
    'colWidths'       => [...],
    'lookupData'      => ['product_name' => $productList],
]);
```

**totalsCallback:**
- Если указано имя функции (например `'applySalesTotals'`) — вызывается после сохранения/обновления вложенной таблицы
- Если не указано (пустая строка) — генерируется функция `apply{Prefix}Totals`, которая обновляет элементы с `data-total-field` атрибутами:
  ```html
  <span data-total-field="total_sum">0.00</span>
  <span data-total-field="total_sum_discount">0.00</span>
  <span data-total-field="pos">0</span>
  ```
- Вызывается в трёх сценариях:
  1. После инлайн-сохранения (onSaveSuccess)
  2. После открытия/закрытия дочерней формы (openChildForm → onRestore)
  3. После нажатия кнопки Refresh (выполняется `_recalc_totals`)

## 5. Форма (`{table}_form.php`)

### 5.1 render_lookup для multiple полей
```php
// Первое вхождение
render_lookup('sotr', 'sotr_id', ..., 'sotr' => $sotrList, ...);

// Второе — тот же lookup-name
render_lookup('sotr', 'sotr2_id', ..., 'sotr' => $sotrList, ...);
```

Оба поля имеют `data-lookup="sotr"`. `form-modal-handler.php` (с фиксом) биндит оба через `querySelectorAll`.

### 5.2 INSERT — все NOT NULL поля
```php
$stmt = $conn->prepare("INSERT INTO docum (...) VALUES (..., ?, 0, 0)");
```
Поля без DEFAULT (`accept_flag`, `voz_flag`) — включить в INSERT с явным значением. **Либо** прописать ALTER TABLE для добавления DEFAULT.

## 6. Проверка после создания (checklist)

- [ ] **Настройка столбцов** — изменить порядок, скрыть колонку → перезагрузить → порядок сохранился
- [ ] **Панель «Условия поиска»** — открыть, видны все поля формы (включая скрытые в таблице)
- [ ] **Поиск по скрытому полю** — найти запись по тексту из невидимой колонки (sotr, note и т.д.)
- [ ] **Колоночные фильтры** — включить/выключить фильтр по Контрагенту, Участку
- [ ] **Инлайн-редактирование** — readonly поля (id, number, sum) не должны редактироваться
- [ ] **Лукапы в форме** — все работают, включая дублирующиеся `data-lookup`
- [ ] **INSERT записи** — сохраняется без ошибок БД (проверить NOT NULL поля)
- [ ] **Параллельное создание** — открыть две формы, сохранить обе, проверить уникальность number
- [ ] **Отметки** — чекбоксы, выделение, фильтр «Показать только отмеченные»
- [ ] **Горячие клавиши** — Enter открыть, Del удалить, Ins добавить
- [ ] **Ресайз колонок** — изменить ширину → перезагрузить → ширина сохранилась (без дрейфа)
- [ ] **JS на странице** — не должно быть ручного инлайн-JS (SearchPanel, SortPanel, ColumnResize, ColumnFilter, marks). Всё через `render_table_page_scripts()`
- [ ] **`marksTbl`** — установлен в конфиге, `handle_marks_actions()` вызван до вывода
- [ ] **Функции отметок** — `clearSelection`, `invertSelection`, `toggleShowOnly` доступны в консоли
- [ ] **Totals дочерней таблицы** — создать/изменить/удалить строку → итоги в родителе обновились
- [ ] **Refresh подтаблицы** — нажать Refresh → итоги в родителе пересчитались


## 7. Требования к создаваемой таблице

ВАЖНО! НИКОГДА нельзя создавать таблицу "с нуля" без использования готового отлаженного шаблона. Таблица это  сложный объект, состоящий из множества стандартных компонентов и алгоритмов. Поэтому создание таблицы "с нуля" влечет  за собой много часов отладки и доведения ее поведения до "стандартного".

Таблица состоит из собственно таблицы со списком записей таблицы базы данных, тулбара (ряда кнопок) над ней и кнопок пагинации под таблицей.

По умолчанию таблица должна иметь полный функционал. Если чего-либо в конкретной таблице не нужно, то это оговаривается в описании этой таблицы. 

## Тулбар таблицы

Над таблицей находится "тулбар" с органами работы с таблицей. В нем находятся (слева направо):

- кнопка "Добавить" (с иконкой add.png)
- кнопка "Изменить" (с иконкой edit.png)
- кнопка "Удалить" (иконка delete.png)
- кнопка "Копировать" (copy.png)
- кнопка "Обновить" (refresh.png) - Перевывести таблицу
- кнопка "Экспорт" (export.php) - открывает меню с пунктами: "Экспорт в CSV" и "Экспорт в Excel"
- кнопка "Печатать" (print.png) - меню с пунктами:
   - Все записи - Сформировать html страницу с таблицей
   - Выбранные
   - Текущая страница
- кнопка "Выбрано NN" - (справа иконка "стрелка вниз") - открывает меню с пунктами:
  - Очистить выбор
  - Инвертировать выбор
  - Показать выбранные. При включении фильтра "Показать выбранные" в информационной строке "Текущий фильтр" выводится: "(Показаны только выбранные)".
  - Экспорт - (экспорт выбранных записей в CSV)
  - Печать - (печать выбранных - в html)
  - Удалить выбранные
- кнопка "Импорт" (import.php) - импорт записей - (для некоторых таблиц)
- поле ввода "Быстрый поиск" - поиск (фильтрация записей) в таблице по заданной подстроке.
- кнопка "Очистить фильтр" - (иконка "x")
- кнопка "Искать" - (иконка find.png)
- кнопка "Условия поиска" - (иконка "стрелка вниз") - открыть панель "Условия поиска"
- кнопка "Сортировка" - (иконка sort.png) - открыть панель "Сортировка"
- кнопка "Настройка столбцов" - (иконка setup.png) - открыть панель "Настройка столбцов таблицы"


Сама таблица "постраничная" с пагинацией и заданным в параметрах настройки числом строк на странице.

В над каждой из колонок таблицы выводится название поля.

Самая левая колонка таблицы состоит из "чекбоксов", предназначенных для отметки записей. Отметки сохраняются ы специальной таблице база данных. В заголовке колонки чекбоксов отметки имеется чекбокс "Отметить все" при помощи которого можно отметить все видимые (отфильтрованные) записи этой таблицы или снять отметки со всех записей. Речь идет о всех записях таблицы, а не о текущей странице.
Если в таблице есть хотя бы одна отмеченная запись, то в тулбаре таблице появляется кнопка с надписью "Выбрано NN", отображающая число отмеченных записей. При нажатии на эту кнопку из нее выпадает меню с такими пунктами:
- Очистить выбор
- Инвертировать выбор
- Показать выбранные - Включает в таблице фильтр "Только выбранные" который выводится в банере состояния фильтра.
- Экспорт - Экспорт отмеченных записей в Excel
- Печать - Сформировать по отмеченным записям страницу с таблицей в формате html
- Удалить выбранные - Опасная функция. Передней выводится запрос на удаление.

В таблице ВСЕГДА должна быть одна выделенная цветом (текущая) строка (по умолчанию первая). С этой строкой работают кнопки тулбара. После операции с выделенной строкой (например изменения или добавления) выделение должно оставаться на этой строке. После удаления строки выделение переходит на следующую строку (если она есть) или на предыдущую строку если удаленная строка была последней. Переход выделения делается с учетом страницы таблицы и направления сортировки таблицы.

В таблице можно изменять ширину колонок путем "перетаскивания" правой границы колонки. Текущая ширина колонки запоминается.

В таблице можно изменять порядок следования колонок и отключать некоторые колонки. Это делается при помощи панели "Настройка столбцов таблицы", которая открывается соответствующей кнопкой тулбара.

Можно сортировать записи в таблице по значению любой колонки путем щелчка по заголовку колонки. Повторный щелч0к по заголовку колонки изменяет порядок сортировки на противоположный. Порядок сортировки показывается иконкой в правой стороне заголовка колонки.

При помощи панели "Сортировка" можно настроить более сложную сортировку по нескольким полям таблицы. Панель "Сортировка" открывается кнопкой тулбара "Сотировка".

В таблице имеется "Быстрый поиск" (фильтрация записей) по заданной подстроке. При включении любого фильтра это фильтр отображается в информационной строке (банере), которая появляется над таблицей. Например: "(Контрагент, Примечание Содержит "Арен")". В левой части информационной строки выводится иконка filter.png, а в правой иконка "X", нажатие на которую выключает этот фильтр). В информационной строке может показываться несколько включенных фильтров, каждый из которых можно отключить при помощи "X". Найденные в полях таблицы подстроки выделяются цветом фона (с учетом заданных "Условий поиска").

Всего есть 3 вида фильтров:
- "Показать только отмеченные"
- "Быстрый фильтр"
- "Колоночный фильтр" по содержимому какой-либо колонки.

У колонок, поля которых заполняются путем выбора из фиксированного списка или из связанной таблицы базы данных, имеется "колоночный фильтр". Он открывается кнопкой "Стрелка вниз" в правой части заголовка колонки. Нажатие на эту кнопку открывает панель выбора одного или нескольких возможных значений поля. Список значений по умолчанию состоит из первых 8-и записей. Слева от каждого значения списка имеется "чекбокс" для выбора этой записи. В нижней части панели "колоночного фильтра" находятся кнопки "Применить" и "Сброс" для включения и сброса колоночного фильтра. Включенный колоночный фильтр показывается в информационной строке над таблицей. Например "(Контрагент = Иванов)".

В таблице имеется возможность редактирования отдельного поля записи без открывания окна формы редактирования записи - "инлайн редактор". При наведении курсора мышки на любую ячейку таблицы (кроме полей "только для чтения") в правой части ячейки появляется кнопка (иконка "карандаш") нажатие на которую открывает панель редактирования поля. В этой панели находится поле для редактирования и кнопки "Сохранить" и "Отменить". Поле редактирования может быть любого допустимого типа: простое поле ввода, textarea, поле выбора (lookup), checkbox, выбор из заданного списка значений и т.п.

В таблице есть возможность "горизонтального скроллинга" ее колонок путем нажатия на клавиши Left и Right. При этом первые 3 колонки таблицы (по умолчанию) не скроллируются - остаются на месте. Остальные колонки при нажатии клавиши Left сдвигаются влево на одну колонку, а при нажатии Right - сдвигаются вправо.

Таблица поддерживает следующие "горячие клавиши":
- Up - перемещение выделения строки вверх на одну строку. С учетом переключения страниц.
- Down - перемещение выделения строки вниз на одну строку. С учетом переключения страниц.
- PgUp - перейти на следующую страницу. Выделение на первой строке новой страницы.
- PgDown - перейти на предыдущую страницу. Выделение на последней строке новой страницы.
- Hоме - перейти к первой строке первой страницы.
- End - перейти к последней строке последней страницы.
- Click - выделить строку
- Double Click - открыть форму редактирования записи
- Enter - открыть форму редактирования записи
- Insert - открыть форму в режиме создания новой записи
- Delete - открыть форму в режиме удаления записи

## 8. Требования к странице формы записи:

Страница формы обычно сделана на базе модального окна.

В верхней части окна формы выводится заголовок состоящий из названия таблицы и дополнительного поля из записи. Например "Клиент: Иванов Иван Петрович", "Счет № 12345"...

Пример заголовка страницы формы "Город": "Город: Москва".
Для новой страницы: "Город (новый)".
Для удаления "Город: Москва (удаление)".
Для копирования "Город: Москва (копия)".

В центре страницы формы расположены поля в для отображения или редактирования (в зависимости от режима формы) полей записи.

Поля могут быть объединены в группы, которые могут иметь свои названия.
Поля могут располагаться как друг под другом так и несколько полей в один ряд по горизонтали (только для экранов desktop и tablet). Порядок расположения полей задается при описании конкретной формы.

Название (label) у поля располагается над полем и выровнено по левой границе поля ввода.
Исключение поле типа checkbox, у которого иконка и label выводятся в одну строку (иконка слева).

Возможные виды полей ввода:

- Обычное поле для ввода с клавиатуры
- Поле выбора из справочника. В правой части этого поля имеется кнопка, нажатие на которую открывает "выпадающий список" для выбора из связанной таблицы-родителя. В верхней части выпадающего списка имеется поле ввода, предназначенное для поиска (фильтрации) данных списка по введенной подстроке.
- Поле выбора из заданного списка вариантов.
- Поле типа "чекбокс".
- Поле переключатель типа "радио кнопки".
- Поле ввода даты с кнопкой, вызывающей "календарь" выбора даты.

В нижней части окна формы находятся кнопки "Применить" (c иконкой accept.png), "Сохранить"  (save.png) и "Отменить" (cancel.png).

В режиме удаления записи кнопка "Сохранить" переименовывается в "Удалить" с иконкой delete.png. В режиме удаления кнопка "Удалить" и заголовок формы имеют красный цвет.

При нажатии на кнопку "Сохранить" запись записывается в базу данных и делается возврат на страницу таблицы, из которой была открыта форма. При этом выделенная строка в таблице должна стоять на данной записи.

При нажатии на кнопку "Удалить" запись удаляется из базы данных и делается возврат на страницу таблицы, из которой была открыта страница формы. При этом выделенная строка в таблице должна стоять на следующей записи.

При нажатии на кнопку "Отменить" ничего не делается а производится только возврат на страницу таблицы, из которой была открыта страница формы.

При нажатии на кнопку "Применить" запись записывается в базу данных но окно формы не закрывается.

При открытии формы курсор (фокус ввода) устанавливается на первое сверху поле (если оно не read only). При нажатии на клавишу Tab курсор последовательно обходит все поля и кнопки в направлении справа налево сверху вниз. С последней кнопки курсор переходит на первое поле. По Shift+Tab - поля обходятся в противоположном направлении.

Контрол, на котором находится фокус ввода, выделяется цветной рамкой шириной в 2 px.


В левой части заголовка страниц таблицы и формы находится иконка, которая зависит от редактируемой таблицы базы данных. Название этой иконки состоит из названия таблицы базы данных (например "city") и расширения ".png".

## 10. Модальная система и stash/restore

### 10.1 Два варианта modal-системы

| Подход | Где используется | Управление stash | Кто биндит форму |
|---|---|---|---|
| `render_form_modal_script()` | Простые формы (city, country, status...) | Автоматически | Шаблон |
| Ручной код (sale.php, invoice.php, plat.php) | Сложные формы с вложенными таблицами | Явно в `openFormModal` | `bindForm()` |

**Никогда не смешивать оба подхода на одной странице** — возникает конфликт двух `stashed`, двух `openFormModal`, дублирование click-обработчиков.

### 10.2 syncFormValues — обязательная операция перед stash

`formBody.innerHTML` сериализует HTML-атрибуты, а не JS-свойства `.value`. Лукап через `choose()` меняет только свойство. Поэтому перед stash:

```js
function syncFormValues(root) {
  (root || formBody).querySelectorAll('input, textarea, select').forEach(function(el) {
    if (el.type === 'checkbox' || el.type === 'radio') {
      if (el.checked) el.setAttribute('checked', ''); else el.removeAttribute('checked');
    } else if (el.tagName === 'SELECT') {
      // ... sync select options
    } else {
      el.setAttribute('value', el.value);
    }
  });
}
```

Вызывать в:
- `openFormModal` перед сохранением `stashed.html`
- `data-lookup-add` обработчике перед stashFn

### 10.3 initFormLookups — привязка лукапов

Лукапы привязываются через `bindLookup()` из `assets/lookup.js`. Данные могут поступать из:
- `window.__storeLookupData` (глобальная переменная, заданная в `<script>`)
- `data-countries` атрибута (JSON в HTML)

Для standalone-режима (прямой доступ к form) **обязательно** вызывать `initFormLookups()` в `initXxxForm()`. Иначе лукапы не привяжутся и hidden-поля останутся `0`.
